# 情緒標註一致性評估

## 這份評估能說什麼、不能說什麼

本次的對照標籤由 **Claude（另一個大型語言模型）**在不看系統答案的情況下產生，
不是人工標註。因此下面的數字是**兩個模型之間的一致率**，
可以指出系統在哪一類容易出錯，但**不能當成「正確率」寫進手冊**——
用模型去驗證模型，兩者可能犯同一種錯而彼此同意。

要得到可寫進手冊的「人工標註正確率」，請由組員依
[怎麼自己重做一次](#怎麼自己重做一次) 的步驟填寫 `sample.csv`，再重新計分。

## 做法

- 母體：`articles` 表中已由 Gemini 評分的 10,212 篇
- 抽樣：**分層隨機**，三類各抽 34 篇後打散，取前 100 篇（亂數種子 20261006，可重現）
- 盲標：`sample.csv` 不含系統標籤，標註時看不到答案
- 標註者看到的字數（1,200 字）比評分器多（150+250 字），
  這樣才驗得出「截斷造成的誤判」

## 結果

樣本一致率 **82.0%**，Cohen's kappa **0.730**（隨機一致期望值 33.3%）。

kappa 0.73 在 Landis & Koch 的分級中屬於 substantial（0.61–0.80），
代表扣掉「碰巧猜對」之後仍有相當高的一致性。

### 混淆矩陣（列＝標註者，欄＝系統）

|  | 正面 | 中性 | 負面 | 小計 |
|---|---|---|---|---|
| **正面** | 30 | 2 | 5 | 37 |
| **中性** | 2 | 30 | 7 | 39 |
| **負面** | 0 | 2 | 22 | 24 |
| **小計** | 32 | 34 | 34 | 100 |

### 各類表現

| 類別 | precision | recall | F1 |
|---|---|---|---|
| 正面 | 0.938 | 0.811 | 0.870 |
| 中性 | 0.882 | 0.769 | 0.822 |
| 負面 | **0.647** | 0.917 | 0.759 |

### 回推母體

樣本是分層抽的，negative 在樣本中佔三分之一、母體只佔 7.5%，
而 negative 正好最弱，所以 82% 低估了實際表現。
依系統標籤在母體中的比例加權後：

| 系統標籤 | 母體佔比 | 同意率 |
|---|---|---|
| 正面 | 34.2% | 93.8% |
| 中性 | 58.4% | 88.2% |
| 負面 | 7.5% | 64.7% |

**加權後約 88.4%。**

## 主要發現：系統傾向把文章判成負面

negative 的 precision 只有 0.647——系統判為負面的 34 篇裡，
有 12 篇標註者認為是正面或中性。recall 卻高達 0.917，
代表它「寧可錯殺」。三種典型的誤判：

1. **褒貶並陳的開箱文**（id=645、7943、932、968）
   同一篇裡「這款很推、那款不推」，系統抓到負面詞就整篇判負面。

2. **提問文被當成抱怨**（id=3984、2896、6206、3821）
   「熊貓針失敗率高嗎」「根管下方有裂紋怎麼辦」是詢問，
   但文中描述的症狀讓系統判成負面。

3. **轉貼新聞**（id=4268）
   醫美集團違法的新聞，內容負面但**發文者本人**沒有表達情緒。

另一個方向的錯誤少得多：標註者認為負面的 24 篇，系統只漏掉 2 篇。

### 反諷的案例

id=9620 標題是「我真的很後悔打嘴巴玻尿酸QQ」，內文第一句卻是
「後悔沒早點打^^」，實際上非常滿意。**系統判對了正面**——
顯示它讀的是內文而不是只看標題。

## 怎麼自己重做一次

1. 重抽樣本（可改種子）：
   ```
   backend\venv\Scripts\python.exe backend\scripts\sample_for_labelling.py
   ```
2. 用 Excel 開 `sample.csv`，在「你的標註」欄填 `positive` / `neutral` / `negative`。
   **填寫期間不要開 `answer_key.json`。**
3. 把填好的內容轉成一行一筆的 `human_labels.txt`：
   ```
   文章id 標籤
   3327 positive
   ```
4. 計分：
   ```
   backend\venv\Scripts\python.exe backend\scripts\score_sentiment_eval.py human_labels.txt
   ```

兩人各標一次、再互相比對，還能算出**標註者之間**的 kappa，
用來說明這個任務本身有多少主觀空間——中性與負面的界線本來就模糊，
人與人之間的一致率通常也到不了 100%。

# 第二輪：試著修正「過度判為負面」

## 結論先講：prompt 怎麼改都量不出差別，真正的問題是別的

針對上面找到的三種誤判，改了三個版本的 prompt，每次都用同一批 100 篇重新評分：

| 版本 | 一致率 | kappa | 加權 | negative precision |
|---|---|---|---|---|
| 原始（第一次評分） | 82.0% | 0.730 | 88.4% | 0.647 |
| v1：加三條規則 | 78.0% | 0.659 | 78.4% | 0.667 |
| v2：收窄「提問一律中性」 | 83.0% | 0.742 | 86.6% | 0.704 |
| v3：只保留新聞那條 | 81.0% | 0.709 | 82.2% | 0.739 |
| **原始 prompt 重跑一次** | **80.0%** | **0.697** | **83.8%** | — |

最後一列是關鍵：**完全沒改 prompt，只是重跑一次，100 篇裡就有 12 篇得到不同標籤**，
一致率從 82.0% 掉到 80.0%。模型本身的隨機性，比三個 prompt 版本之間的差距還大。

v1 明顯更差（它把「提問一律算中性」，結果把「客服聯絡不上」「賣家要我改五星」
這類真正的抱怨也掃成中性，negative recall 從 0.917 掉到 0.500）。
v2 與 v3 則都落在原始 prompt 自己重跑的波動範圍內——**無法宣稱有改善**。

逐篇看也是一樣：v2 修對 8 篇、同時弄錯 7 篇，淨增 1 篇。n=100 時這等於沒有差別。

因此 **prompt 改動全部退回**，保留原始版本。

## 改了什麼（這兩項有實測效果）

### 1. 分類改用 temperature 0

`llm_client` 原本所有用途共用 `temperature=0.3`。產生式任務（問答、洞察）
留一點變化是合理的，但分類要的是「最可能的那個標籤」，變化只會變成雜訊。

| | 同一組 prompt 重跑兩次 |
|---|---|
| temperature 0.3 | **12/100 篇標籤不同** |
| temperature 0 | **0/100 篇不同** |

這不只是數字好看：**在 12% 雜訊下，任何小於 10 個百分點的改善都量不出來**。
把雜訊降到 0 之後，以後再調 prompt 才有辦法判斷到底有沒有變好。

temperature 0 下的表現：一致率 82.0%、加權 85.7%、negative precision 0.667。

### 2. 修掉會整批吞掉 20 篇的 JSON 解析

實測抓到一次模型在合法 JSON 後面多吐三個字元：

```
{"results": [{"id": 6786, "sentiment": "positive"}]}
}]}
```

舊版把整串交給 `json.loads`，一失敗就回 `{}`，**那一批 20 篇全部當成沒評到**。
改用 `JSONDecoder().raw_decode()`：解析出第一個完整的 JSON 值就停，
後面多餘的字元不影響前面正確的部分。已補三個單元測試。

這就是先前 1,074 篇卡住的同一類問題——失敗時沒有任何訊息，只會看到「還沒評分」。

## 原本的問題解決了嗎：**沒有**

negative 的 precision 從 0.647 到 0.667，**在雜訊範圍內，不算改善**。
系統仍然會把褒貶並陳的開箱文、帶抱怨的提問文判成負面。

誠實的說法是：這個邊界有一部分是**任務本身就模糊**，不是純粹的程式缺陷。
回頭檢查時發現，有幾篇所謂「系統判錯」的例子，標註者的標籤同樣可以商榷：

- id=2896「[請益] 推薦的修復霜」文中寫「B5 是我的毒藥」「用了開始長痘」，
  判 negative 其實站得住腳
- id=6206 唇釉「不太適合我」、粉餅卡不住，也確實帶著不滿

要真正推進這件事，需要的是：
1. **人工標註**取代模型標註（見上半部的步驟）
2. **更大的樣本**：n=100 時，±7 個百分點都在 95% 信賴區間內，
   小改善根本偵測不到
3. 兩人各標一次，先算出**標註者之間**的 kappa，
   知道人類自己能到多少，才知道系統還差多遠
