# 情緒分析模型成效評估

## 為什麼要做這件事

系統宣稱提供「AI 情緒分析」，但若沒有量化評估，就無法回答最基本的問題：
**模型判得多準？哪一類最容易判錯？**

這份評估以人工標註樣本為基準，計算 accuracy、各類別 precision / recall / F1
與混淆矩陣。

## 樣本設計

| 子集 | 數量 | 用途 |
|---|---|---|
| `random` | 75 | 從已評分文章隨機抽樣，估計**整體正確率** |
| `negative_boost` | 25 | 補抽模型判為 negative 的文章 |

**為什麼要補抽負面樣本？**
負面文章在隨機樣本中僅約 8%，只有 6 篇的話 F1 會極不穩定（少判對一篇就差 15%）。
補抽後 negative 有 29 篇，統計才可靠。

**代價是類別比例被人為改變**，所以「整體正確率」**只用 random 子集計算**，
避免被放大的負面比例扭曲；各類別 precision / recall 則使用全部樣本。

## 標註原則

判斷「**發文者本人**」的情緒（不是留言者，也不是文章主題的好壞）：

- `positive` — 滿意、推薦、分享正面經驗
- `negative` — 抱怨、後悔、副作用、糾紛、負面經驗
- `neutral` — 提問、討論、資訊分享、看不出明顯情緒

實務上最常見的邊界情況是「**提問中夾帶抱怨**」。判準：以**主要行為**為準——
若整篇的核心是求推薦、問方法，即使句中有一句抱怨，仍標為 `neutral`；
若核心是陳述自己遭遇的不好經驗，才標為 `negative`。

## 結果（2026-09）

**整體正確率（n=75 隨機子集）：90.7%**

| 類別 | 樣本數 | precision | recall | F1 |
|---|---|---|---|---|
| positive | 16 | 0.833 | 0.938 | 0.882 |
| neutral | 55 | 0.940 | 0.855 | 0.895 |
| negative | 29 | 0.812 | 0.897 | **0.852** |

混淆矩陣（列＝人工標註，欄＝模型判斷）：

|  | positive | neutral | negative |
|---|---|---|---|
| **positive** | 15 | 1 | 0 |
| **neutral** | 2 | 47 | 6 |
| **negative** | 1 | 2 | 26 |

### 解讀

- **負面召回率 0.897** 是輿情系統最重要的指標：真正的負面聲量有近九成被抓到。
  漏掉負面討論的代價，遠高於誤報。
- **主要錯誤是「中性被判成負面」（6 篇）**。多為提問中帶抱怨的文章，
  例如「水光槍打完臉紅點很多」——本質是詢問，但用詞聽起來像抱怨。
  這個方向的誤差對輿情監控相對安全（寧可多看一篇，不要漏掉）。
- **positive precision 最低（0.833）**：有 2 篇中性文被判成正面，
  多為產品開箱文中夾雜好評但整體是資訊分享。

## 已知限制

1. **標註者是另一個語言模型（Claude），不是人類。**
   標註時閱讀的是文章**全文**（多數樣本 800 字內即完整），
   而受測模型只讀開頭 150 + 結尾 250 字，因此兩者資訊量不同，
   這是刻意的設計——若用同一段截斷文字標註，量到的只是「兩個模型是否同意」，
   而不是「模型判得對不對」。
   即便如此，這仍**不等同於人類標註**，正式報告中應說明此點，
   或請人重新檢核部分樣本。

2. **樣本以 PTT 為主**（隨機抽樣反映實際資料分布，PTT 佔 97%），
   Dcard / Mobile01 / Threads 的樣本過少，無法個別評估。

3. **n=75 的信賴區間不窄**：90.7% 的 95% 信賴區間約為 ±6.6%。
   要更精確需擴大樣本。

## 重新執行

```bash
python evaluation/evaluate_sentiment.py
```

修改模型或 prompt 後重跑，即可比較成效變化。
若要擴充樣本，於 `sample.json` 新增項目並填寫 `gold_label` 即可。
